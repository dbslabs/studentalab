Phase 1 — OS Installation & Recovery (Weeks 1–3)

You will perform a clean installation of Windows 10 on your primary workstation, explore the Windows Recovery Environment, and practice creating and restoring system restore points. These are foundational skills for every task that follows[cite: 6].

Lab 1-A: BIOS/UEFI Exploration

Before installing any operating system you must understand the firmware interface of your machine[cite: 6].

Your tasks:

  • Boot the OptiPlex 3020 #1 into the BIOS/UEFI setup utility[cite: 6].
  • Locate and record: the current boot order, the Secure Boot status, and the SATA operation mode[cite: 6].
  • Change the boot order so that USB boots before the internal drive. Save and exit[cite: 6].
  • Identify whether the system uses Legacy BIOS or UEFI. Write down how you determined this[cite: 6].

Think about this:

  • What is the difference between Legacy BIOS boot and UEFI boot?[cite: 6]
  • How does Secure Boot affect what operating systems you can install?[cite: 6]
  • What SATA mode is required for Windows 10 to detect your drive correctly during installation?[cite: 6]

Verification checklist:

  • Boot order changed and saved successfully[cite: 6]
  • Boot mode (Legacy / UEFI) identified and documented[cite: 6]
  • Secure Boot status recorded[cite: 6]

Lab 1-B: Clean Windows 10 Installation

You will perform a fresh installation of Windows 10 Pro on OptiPlex 3020 #1. Your installation media is a bootable USB drive created with the Microsoft Media Creation Tool[cite: 6].

Your tasks:

  • Boot from the USB drive. Walk through the installation wizard[cite: 6].
  • When you reach the partitioning screen, delete all existing partitions. Create two partitions: one for the OS (minimum 60 GB, label it C:) and one for data (label it D:). Record the sizes you chose and why[cite: 6].
  • Complete the installation. Configure a local administrator account. Do not sign in with a Microsoft account[cite: 6].
  • After the first boot, open Device Manager. Identify any devices showing errors or missing drivers. Research and install any missing drivers[cite: 6].
  • Document the Windows edition, version number, and build number (Settings > System > About)[cite: 6].

Important Note: OptiPlex 3020 #1 will later become your Domain Controller. Ensure your partition layout leaves enough space. Do not join a domain or connect to the internet until instructed[cite: 6].

Verification checklist:

  • Windows 10 Pro installed and booting normally[cite: 6]
  • Two partitions created (C: system, D: data)[cite: 6]
  • Device Manager shows no errors[cite: 6]
  • Windows version and build number documented[cite: 6]

Lab 1-C: System Restore Points

Restore points allow you to roll Windows back to a previous configuration state without affecting personal files. You will create one manually, make changes to the system, then restore it[cite: 6].

Your tasks:

  • Open System Properties and confirm that System Protection is enabled on the C: drive. If it is not, enable it and set an appropriate disk space allocation[cite: 6].
  • Create a restore point manually. Give it a meaningful description that includes today's date[cite: 6].
  • Make at least two noticeable changes to the system: install a small application, change a system setting, and add a desktop shortcut[cite: 6].
  • Use System Restore to roll back to the restore point you created. Confirm the changes you made are gone[cite: 6].
  • Research and answer: what does System Restore NOT protect? What files and settings are excluded?[cite: 6]

Verification checklist:

  • System Protection confirmed enabled on C:[cite: 6]
  • Restore point created and named[cite: 6]
  • Changes made and then rolled back successfully[cite: 6]
  • Exclusions documented[cite: 6]

Lab 1-D: Windows Recovery Environment (WinRE)

Windows RE is a recovery platform built into Windows. You must know how to access it and what each tool does[cite: 6].

Your tasks:

  • Access WinRE using the Shift + Restart method from inside Windows. Document this path[cite: 6].
  • From the WinRE menu, identify and write down all available troubleshooting tools[cite: 6].
  • Commands: Open Command Prompt within WinRE. Run the following commands and document what each one does and what output you see: sfc /scannow | DISM /Online /Cleanup-Image /RestoreHealth | bootrec /scanos[cite: 6]
  • Use Startup Repair on a machine that is booting normally. Observe the output. What does it report?[cite: 6]
  • Research: what is the difference between Refresh your PC and Reset your PC in Windows recovery options? When would you use each one?[cite: 6]

Warning: Do not run bootrec /fixmbr or /fixboot. These commands rewrite the master boot record. Only use them if instructed and on the correct machine[cite: 6].

Verification checklist:

  • WinRE accessed and all tools listed[cite: 6]
  • SFC and DISM outputs documented[cite: 6]
  • Startup Repair result recorded[cite: 6]
  • Reset options compared and documented[cite: 6]

Lab 1-E: Second Machine Preparation

Your tasks:

  • Set a static IP address: 172.16.100.50 / 255.255.255.0. Do not set a gateway or DNS yet[cite: 6].
  • Verify that both machines can ping each other by IP address[cite: 6].

Verification checklist:

  • Ping between #1 and #2 successful[cite: 6]

Phase 2 — Windows Server 2019 & Active Directory (Weeks 4–6)

You will install Windows Server 2019 Essentials on OptiPlex 3020 #1, promote it to a Domain Controller, and build the directory infrastructure that all other lab machines will join. Student B cannot join the domain until your DC is fully operational[cite: 6].

Lab 2-A: Windows Server 2019 Installation

Your tasks:

  • Install Windows Server 2019 Essentials on OptiPlex 3020 #1. Use the same partition you prepared in Phase 1 or reinstall fresh if directed[cite: 6].
  • After installation, set a static IP address: 172.16.100.10 / 255.255.255.0. Set the gateway to 172.16.100.1 and set the DNS server to 127.0.0.1[cite: 6].
  • Set the computer name to DC01 before promotion[cite: 6].
  • Run Windows Update and document which updates were applied[cite: 6].

Verification checklist:

  • Server 2019 installed and booting[cite: 6]
  • Computer name set to DC01[cite: 6]
  • Static IP 172.16.100.10 configured[cite: 6]
  • Windows Update run and patches documented[cite: 6]

Lab 2-B: Active Directory Domain Services

You will add the AD DS role and promote DC01 to a Domain Controller. This creates your lab domain[cite: 6].

Your tasks:

  • Open Server Manager. Add the Active Directory Domain Services role[cite: 6].
  • After role installation, promote the server to a Domain Controller. Create a new forest with the domain name lab.local[cite: 6].
  • After the reboot, verify that DNS is working. Open DNS Manager and confirm the lab.local forward lookup zone exists[cite: 6].
  • In Active Directory Users and Computers, create the following Organizational Units: IT, Students, Computers[cite: 6].
  • Create two domain user accounts: studentA (place in Students OU) and studentB (place in Students OU). Set passwords that meet complexity requirements[cite: 6].
  • Explain in your documentation: what is the difference between a local account and a domain account?[cite: 6]

Verification checklist:

  • AD DS role installed[cite: 6]
  • DC01 promoted, domain lab.local active[cite: 6]
  • DNS forward lookup zone confirmed[cite: 6]
  • OUs created: IT, Students, Computers[cite: 6]
  • User accounts studentA and studentB created[cite: 6]

Lab 2-C: DHCP Server

Configure a DHCP scope so that machines joining the lab network receive addresses automatically. You must ensure your scope does not conflict with any existing network equipment[cite: 6].

Your tasks:

  • Add the DHCP Server role in Server Manager[cite: 6].
  • Create a scope named Lab Scope with the following range: 172.16.100.50 to 172.16.100.100. Subnet mask: 255.255.255.0. Default gateway: 172.16.100.1. DNS: 172.16.100.10[cite: 6].
  • Add exclusions for any static IP addresses already assigned (your server at .10, proxy at .50, and Student B's machines)[cite: 6].
  • Authorize the DHCP server in Active Directory[cite: 6].
  • Verify that a test machine receives a lease. Document the lease details[cite: 6].

Network Conflict Reminder: Your lab is on VLAN 11 (172.16.100.x). The school network operates on 192.168.40.x. Lab ports on the switch are 7-12 and 31-36 only. These are separate networks. Your DHCP server cannot reach 192.168.40.x clients. Do not change the scope range without instructor approval[cite: 6].

Verification checklist:

  • DHCP role installed and authorized[cite: 6]
  • Scope 172.16.100.50–.100 created[cite: 6]
  • Exclusions added for static devices[cite: 6]
  • Test machine receives lease and has connectivity[cite: 6]

Lab 2-D: Shared Folders, Drive Mapping & Group Policy

You will create shared folders with appropriate permissions, then use Group Policy to automatically map them for domain users[cite: 6].

Your tasks:

  • On DC01, create two shared folders on the D: drive: one named Staff (accessible to all domain users, read only) and one named IT (accessible only to members of the IT OU, full control)[cite: 6].
  • For each folder, configure both Share permissions and NTFS permissions. Document what each permission level does and why both matter[cite: 6].
  • In Group Policy Management, create a new GPO named Drive Mapping. Link it to the Students OU. Configure it to map \\DC01\Staff to the Z: drive for all domain users[cite: 6].
  • Test by logging into a domain-joined machine as studentB. Verify the Z: drive appears. If it does not, use gpupdate /force and troubleshoot[cite: 6].
  • Create a second GPO that sets a desktop wallpaper of your choice for all domain computers. Verify it applies[cite: 6].

Verification checklist:

  • Staff and IT shares created with correct permissions[cite: 6]
  • Drive mapping GPO created and linked[cite: 6]
  • Z: drive appears on domain client machines[cite: 6]
  • Wallpaper GPO confirmed applying[cite: 6]

Lab 2-E: Connecting the MacBook Air

Your MacBook Air must connect to the lab.local domain and access shared resources. This requires specific configuration on both the Mac and the server[cite: 6].

Your tasks:

  • Configure the MacBook Air with a static IP: 172.16.100.40 / 255.255.255.0. Gateway: 172.16.100.1. DNS: 172.16.100.10[cite: 6].
  • Verify the Mac can ping DC01 by IP and by hostname (ping dc01.lab.local)[cite: 6].
  • Join the Mac to lab.local using Directory Utility. Research the correct method for your macOS version[cite: 6].
  • Log into the Mac using the studentA domain account. Confirm the home folder is created[cite: 6].
  • From Finder, connect to the Staff share (Go > Connect to Server > smb://dc01/staff). Map it and verify file access[cite: 6].
  • Document any errors encountered and how you resolved them. Mac-to-Windows SMB connections frequently have compatibility issues — research the common causes[cite: 6].

Verification checklist:

  • Mac joined to lab.local[cite: 6]
  • Domain login successful on Mac[cite: 6]
  • SMB share accessible from Finder[cite: 6]
  • Errors and resolutions documented[cite: 6]

Phase 3 — Remote Access, Security & Web Services (Weeks 7–9)

Lab 3-A: Remote Desktop Protocol (RDP)

Your tasks:

  • Enable RDP on DC01 via System Properties > Remote[cite: 6].
  • Add both studentA and studentB to the Remote Desktop Users group[cite: 6].
  • From Student B's machine, connect to DC01 using the Remote Desktop Connection client (mstsc). Log in as studentA[cite: 6].
  • Test clipboard redirection and drive redirection within the RDP session[cite: 6].
  • Research and document: what port does RDP use by default? How would you change it? What are the security implications?[cite: 6]

Verification checklist:

  • RDP enabled on DC01[cite: 6]

Lab 3-B: IIS Web Server & HTTPS with Certificate Manager

You will install IIS, create a website, generate a self-signed certificate, and configure HTTPS. This lab covers the full certificate lifecycle in a controlled environment[cite: 6].

Your tasks:

  • Install the Web Server (IIS) role on DC01 via Server Manager[cite: 6].
  • Browse to http://dc01 from a domain-joined client machine. Document what you see and why it works without further configuration[cite: 6].
  • Create a simple HTML file and place it in the IIS default website root. Verify it displays in a browser[cite: 6].
  • Open IIS Manager. Navigate to Server Certificates. Create a self-signed certificate. Name it DC01 Lab Cert[cite: 6].
  • Add an HTTPS binding to the default website on port 443. Assign the certificate you just created[cite: 6].
  • Browse to https://dc01 from a client machine. A security warning will appear. Document exactly what the warning says and why it appears[cite: 6].
  • Export the certificate from the server. Import it into the Trusted Root Certification Authorities store on a client machine using certmgr.msc. Verify the browser warning disappears[cite: 6].
  • In your documentation, explain: what makes a certificate trusted? What is the difference between a self-signed certificate and one issued by a Certificate Authority?[cite: 6]

Verification checklist:

  • IIS installed and default page loading[cite: 6]
  • Custom HTML page served over HTTP[cite: 6]
  • Self-signed certificate created[cite: 6]
  • HTTPS binding configured on port 443[cite: 6]
  • Certificate imported and HTTPS warning resolved on client[cite: 6]

Lab 3-C: Proxy Server Configuration

OptiPlex 3020 #2 will be configured as a proxy server. Lab clients will route their internet traffic through it. This simulates a common enterprise security architecture[cite: 6].

Your tasks:

  • On OptiPlex #2, join it to the lab.local domain. Set its static IP to 172.16.100.50[cite: 6].
  • Install a proxy server application on OptiPlex #2. Research available options for Windows and select an appropriate one. Document your choice and why[cite: 6].
  • Configure the proxy to listen on port 3128 (or the default for your chosen application)[cite: 6].
  • On a client machine, configure the browser and system proxy settings to point to 172.16.100.50 on the appropriate port[cite: 6].
  • Verify that the client can reach the internet through the proxy. Verify that if the proxy service is stopped, the client loses internet access[cite: 6].
  • Review the proxy logs. Document what information is recorded about client requests[cite: 6].

Verification checklist:

  • Proxy application installed on OptiPlex #2[cite: 6]
  • Client proxy settings configured[cite: 6]
  • Internet access confirmed through proxy[cite: 6]
  • Proxy log entries reviewed and documented[cite: 6]

Lab 3-D: WinRM Remote Management

Windows Remote Management (WinRM) allows command-line remote administration of Windows machines using PowerShell[cite: 6].

Your tasks:

  • On DC01, open an elevated PowerShell window. Run winrm quickconfig and accept all prompts. Document what changes it makes[cite: 6].
  • From a domain-joined client machine, open PowerShell. Connect to DC01 remotely using Enter-PSSession[cite: 6].
  • Once connected, run at least three commands remotely: check running services, view event log entries, and check disk space. Document the commands and output[cite: 6].
  • Use Invoke-Command to run a script block on DC01 without entering an interactive session. Document the difference between Enter-PSSession and Invoke-Command[cite: 6].
  • Research and document: what firewall rule does WinRM require? How is WinRM different from RDP?[cite: 6]

Verification checklist:

  • WinRM configured on DC01[cite: 6]
  • Remote PowerShell session established from client[cite: 6]
  • Remote commands executed and documented[cite: 6]
  • Difference between Enter-PSSession and Invoke-Command explained[cite: 6]
